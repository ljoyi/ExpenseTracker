# P0 需求冻结与验收标准

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 版本 | P0 v1.0 |
| 状态 | 已冻结 |
| 冻结日期 | 2026-09-10 |
| 目标用户 | 需要快速记录个人日常收支的 iPhone 用户 |
| 目标平台 | iOS 17 及以上 |
| 首发形态 | iPhone 竖屏 |
| 数据模式 | 单设备、单账本、本地存储、无登录 |

## 2. P0 目标

P0 只验证一条核心闭环：

**快速记录一笔账 -> 按日期找到这笔账 -> 看懂当前周期的收支概况 -> 修改或删除后数据一致。**

成功标准：

- 新用户不需要注册或初始化配置即可开始记账。
- 普通支出从进入记账页到保存完成，目标不超过 10 秒。
- 新增、修改、删除后，账单页、日历、汇总和统计全部同步。
- App 离线可用，重启后数据不丢失。
- 1,000 条账单下仍可正常浏览、切换和统计。

## 4. 全局业务规则

### 4.1 交易类型

- P0 只有“支出”和“收入”两种类型。
- 金额始终以正数输入和保存，类型决定其在汇总中的方向。
- 支出记为负向金额，收入记为正向金额。
- 转账不进入 P0，不创建伪转账分类替代转账。

### 4.2 金额

- 金额界面不显示货币符号。
- 所有展示金额统一保留两位小数。
- 单笔金额必须大于 `0.00`。
- 单笔金额最多两位小数。
- 单笔金额上限为 `99,999,999.99`。
- 金额内部按“分”保存为 `Int64`，界面输入和展示使用十进制字符串。
- 汇总公式使用整数分运算，不使用浮点数。

### 4.3 时间

- 新增账单时默认使用设备当前日期和时间。
- 用户可以修改账单发生的日期和时间。
- 日期时间精确到分钟。
- P0 支持选择未来时间，未来账单参与对应日期、月份、年份和全部范围的统计。
- 月份、年份和每日分组使用设备当前日历与时区。
- 账单排序规则：先按发生时间倒序，同一时间再按创建时间倒序。
- 月份范围采用左闭右开区间，避免跨月重复统计。

### 4.4 分类

- P0 只提供内置分类，不提供新增、修改、排序和删除分类。
- 分类必须属于“支出”或“收入”其中一种类型。
- 账单类型与分类类型必须一致。
- 每个账单必须关联一个分类，不允许无分类账单。
- 内置分类不可删除。

### 4.5 删除

- P0 删除为永久删除，不提供回收站和撤销。
- 删除前必须弹出二次确认。
- 删除成功后，账单页、日历、汇总和统计立即更新。
- 重复触发删除不能产生异常数据或重复删除。

## 5. 详细需求与验收

### FR-01 首次启动与默认账本

对应需求：`M01`

功能规则：

- 首次启动自动创建“我的账本”。
- 同一次启动同时写入 P0 内置分类。
- 初始化必须原子完成，不能出现只有账本没有分类的状态。
- 后续启动直接复用已有默认账本，不能重复创建。

验收标准：

- Given 用户首次安装并启动 App，When 进入账单页，Then 已存在“我的账本”和完整内置分类。
- Given 用户重启 App，When 再次进入首页，Then 仍只有同一个默认账本。
- Given 初始化中途发生错误，When 用户重新启动，Then 系统可完成初始化且不产生重复数据。

### FR-02 主导航

对应需求：`M02`

功能规则：

- 底部导航固定为“账单、统计、我的”。
- 默认选中“账单”。
- 从其他页面返回时保留当前主导航状态。
- “我的”在 P0 仅为占位页，不提供设置功能。

验收标准：

- Given App 已启动，When 用户启动完成，Then 默认进入账单页。
- Given 用户点击任一主导航，When 页面切换完成，Then 选中状态与页面内容一致。
- Given 用户返回账单页，When 页面重新出现，Then 月份和选中日期保持合理状态或按明确规则重置。

### FR-03 月度概要与月份切换

对应需求：`M03`、`M04`

功能规则：

- 默认展示设备当前月份。
- 概要以所选月份为唯一统计范围。
- 展示当月支出、收入、结余。
- 结余等于当月收入减当月支出，可以为负。
- 切换月份后，概要、日历和每日账单列表必须同步切换。

验收标准：

- Given 某月有收入和支出，When 打开对应月份，Then 三项金额与账单明细汇总一致。
- Given 用户切换到另一个月份，When 切换完成，Then 三个区域使用同一个月份，不出现串月。
- Given 某月没有账单，When 打开该月，Then 收入和支出均显示 `0.00`，结余显示 `0.00`。

### FR-04 日历视图

对应需求：`M05`

功能规则：

- 日历按月显示完整周布局。
- 每个日期展示收入、支出或“有账”标记。
- 选中日期在视觉上高亮。
- 没有账单的日期仍可选择。
- 月份切换后，日历标题、日期范围和每日标记同步更新。

验收标准：

- Given 当月某日有账单，When 日历加载完成，Then 该日显示正确的有账状态。
- Given 用户选中某日，When 选中完成，Then 日期高亮，下方列表只显示该日账单。
- Given 用户切换月份，When 完成切换，Then 日历不显示上月的日期数据。

### FR-05 每日账单卡片与详情

对应需求：`M06`、`M07`

功能规则：

- 账单按日期分组，每个有账日期生成一个卡片。
- 卡片标题展示日期、星期、收入、支出。
- 没有收入的日期不显示收入，没有支出的日期不显示支出。
- 条目展示时间、分类和金额。
- 收入显示 `+` 和收入色，支出显示 `-` 和支出色。
- 点击条目进入账单详情。

验收标准：

- Given 一个月内存在多天账单，When 用户浏览列表，Then 只出现有账日期，且日期倒序排列。
- Given 某日有收入和支出，When 查看卡片标题，Then 收入与支出均正确显示。
- Given 用户点击条目，When 详情打开，Then 金额、类型、分类、日期时间与保存数据一致。

### FR-06 新增账单

对应需求：`M10-M14`

功能规则：

- 账单页显示固定“+”按钮。
- 点击后打开新增账单页。
- 默认类型为支出。
- 默认时间为当前时间。
- 分类必须由用户明确选择，不默认替用户选择。
- 金额为空、为 `0`、格式非法或超过上限时不能保存。
- 保存成功后返回账单页，并刷新相关月份、日期和统计。

验收标准：

- Given 用户在账单页，When 点击“+”，Then 打开空白新增账单页。
- Given 用户选择支出、输入合法金额并选择支出分类，When 点击保存，Then 账单写入数据库并出现在对应日期。
- Given 用户未选择分类，When 点击保存，Then 保存被阻止并提示选择分类。
- Given 用户输入非法金额，When 点击保存，Then 保存被阻止且保留当前输入。
- Given 用户切换为收入，When 展开分类，Then 只显示收入分类。
- Given 用户选择晚于当前时间的日期，When 尝试保存，Then 保存被阻止并提示时间非法。

### FR-07 金额输入

对应需求：`M12`

功能规则：

- 使用应用内数字键盘或受控数字输入。
- 支持数字 `0-9`、小数点和删除。
- 只允许一个小数点。
- 小数点后最多两位。
- 不以无意义的前导多个 `0` 展示。
- 保存按钮在金额无效时禁用。

验收标准：

- Given 用户输入 `12.34`，When 保存，Then 数据库保存 `1234` 分。
- Given 用户继续输入第三位小数，When 点击数字，Then 新输入被拒绝。
- Given 用户先输入小数点，When 输入完成，Then 可正确形成 `0.x`，无需手动补前导零。
- Given 金额为空或为 `0`，When 查看底部操作区，Then 保存不可用。

### FR-08 修改与删除

对应需求：`M08`、`M09`

功能规则：

- 详情页提供修改和删除。
- 修改复用记一笔表单，并预填原数据。
- 修改分类时必须保证分类类型与账单类型一致。
- 修改后返回详情或账单页，全部相关视图立即同步。
- 删除前显示二次确认。
- 删除后返回账单页。

验收标准：

- Given 用户打开已有账单，When 进入修改，Then 原类型、金额、分类、日期和时间均已预填。
- Given 用户把支出改为收入，When 保存，Then 原支出分类不能继续被使用。
- Given 用户将金额从 `10.00` 改为 `20.00`，When 保存完成，Then 列表、月度概要和统计都只按 `20.00` 计算。
- Given 用户点击删除，When 确认删除，Then 该账单从所有视图中消失。
- Given 用户点击删除但取消，When 返回详情，Then 原账单保持不变。

### FR-10 统计周期与总览

对应需求：`M21`、`M22`

功能规则：

- 默认周期为“本月”。
- 支持本月、上月、今年、去年、近一年、全部和自定义日期。
- 自定义日期必须满足开始日期不晚于结束日期。
- 所有统计模块必须使用同一个日期范围。
- 总览展示总收入、总支出、结余、日均支出。

验收标准：

- Given 用户首次进入统计页，When 页面加载完成，Then 默认显示本月数据。
- Given 用户切换周期，When 切换完成，Then 总览和分类占比同步使用新范围。
- Given 某周期没有账单，When 查看总览，Then 三项金额均为 `0.00`，日均支出为 `0.00` 或明确的空值提示。

### FR-11 分类占比

对应需求：`M23`

功能规则：

- 支持切换支出和收入。
- 使用饼图展示各分类金额占比。
- 图表旁或列表展示分类名称、金额、占比。
- 分类按金额从高到低排序。
- 金额相同按分类预置顺序排序，再按名称排序，保证顺序稳定。
- 点击分类进入该分类在当前周期内的账单列表。

验收标准：

- Given 周期内存在支出，When 查看支出分类，Then 各分类金额之和等于总支出。
- Given 某分类占比为 `25.0%`，When 页面展示，Then 图表和文字使用同一数值。
- Given 用户点击“餐饮”，When 进入分类明细，Then 列表只包含当前周期内的餐饮账单。
- Given 周期内没有收入，When 查看收入分类，Then 显示明确空状态，不显示错误饼图。

### FR-12 本地持久化

对应需求：`M26`

功能规则：

- 账单、分类和账本均保存在本机。
- P0 不依赖网络，飞行模式不影响核心功能。
- 新增、修改、删除必须在数据库提交成功后才向用户显示成功。
- 保存失败时必须保留用户输入并显示可重试提示。

验收标准：

- Given 用户新增一笔账单，When 强制关闭并重启 App，Then 账单仍存在。
- Given 用户修改账单，When 重启 App，Then 显示修改后的值。
- Given 用户删除账单，When 重启 App，Then 账单不会恢复。
- Given 设备处于飞行模式，When 完成记账全流程，Then 所有核心功能正常工作。

## 6. 页面状态最低要求

所有核心页面必须实现以下通用状态：

| 状态 | 要求 |
| --- | --- |
| 初始加载 | 只出现在需要读取数据的短暂阶段，避免无反馈白屏 |
| 正常内容 | 数据和操作完整可用 |
| 空状态 | 有解释文字和下一步入口，不只显示空白 |
| 局部无数据 | 例如某日无账单、某类型无分类统计 |
| 表单校验错误 | 指明字段和原因，不清空用户输入 |
| 保存中 | 防止重复提交，保留当前内容 |
| 保存失败 | 明示失败原因并提供重试 |
| 删除确认 | 明确账单摘要，提供取消和确认 |
| 删除失败 | 保留原账单，允许重试 |
| 致命读取失败 | 显示错误说明，不展示错误的零值或假数据 |

## 7. 非功能要求

### 性能

- App 冷启动后应尽快显示账单骨架和本地数据。
- 新增、修改、删除后，列表和统计刷新目标为 300 毫秒内。
- 1,000 条账单下，月份切换和按日筛选保持可交互。
- 统计计算不得阻塞主线程超过可感知范围；必要时使用异步计算。

### 数据一致性

- 金额、类型和分类关系由 Service 统一校验。
- 列表、汇总和统计不得各自实现不同的金额符号规则。
- 删除和修改成功后必须触发同一数据源的刷新，不维护独立副本。

### 可访问性

- 收入与支出不能只依赖绿色和红色区分，必须同时使用正负号或文字。
- 图标按钮必须提供可访问性标签。
- 金额、分类和日期控件应支持系统动态字体，且在较大字号下不重叠。

### 本地化

- P0 界面语言为简体中文。
- 金额格式统一使用人民币。
- 日期和星期名称使用系统本地化输出。

## 8. 明确不在 P0 范围

- 备注录入、连续记账和快捷保存。
- 新增、修改、删除和排序自定义分类。
- 趋势图、日/月报表和预算。
- 多账本和账本切换。
- 账户、银行卡、信用卡和余额。
- 转账、退款、报销和图片附件。
- 搜索、账单导出和数据恢复。
- iCloud、登录、多设备和多人共享。
- iPad、横屏、Widget、Apple Watch 和快捷指令。

## 9. P0 验收清单

- [ ] 首次启动只创建一个默认账本，并完成内置分类初始化。
- [ ] 默认进入账单页，底部三个导航入口可正常切换。
- [ ] 月度概要、日历和账单列表使用同一月份。
- [ ] 可新增支出和收入，金额、分类、日期时间校验正确。
- [ ] 新增后自动出现在正确的日期分组和统计范围。
- [ ] 可打开详情并修改类型、金额、分类、日期和时间。
- [ ] 修改后的列表、汇总和统计不存在旧值或重复计算。
- [ ] 删除必须二次确认，删除后所有视图同步更新。
- [ ] 统计支持 P0 规定的周期，总览金额与明细一致。
- [ ] 分类占比金额之和等于总览金额，分类明细可下钻。
- [ ] 空状态、校验错误、保存错误和删除错误均有明确反馈。
- [ ] App 重启后数据不丢失，飞行模式不影响核心功能。
- [ ] 1,000 条账单下核心操作保持可用。
