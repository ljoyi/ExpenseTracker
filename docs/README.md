## 已冻结的产品范围

P0 只包含以下 19 个需求：

`M01-M14`、`M17`、`M21-M23`、`M26`

四个核心页面为：

- 账单页
- 记一笔页
- 账单详情页
- 统计页

底部导航保留“账单、统计、我的”。其中“我的”在 P0 只提供占位页，不承载设置功能。

## 已冻结的技术决策

- 使用 SwiftUI 构建界面。
- 使用 SwiftData 保存本地数据。
- 使用 Swift Charts 展示分类占比饼图。
- 使用 SF Symbols 提供系统图标。
- 使用轻量 MVVM 和功能优先的目录结构。
- 不引入后端、不引入账号体系、不引入第三方依赖。
- 金额不使用 `Double`，统一按人民币“分”保存为 `Int64`。
- P0 使用内置分类，不提供新增、修改和删除分类。
- P0 不提供备注、连续记账、趋势图、日/月报表、账户、预算、转账和退款。
- 支持记录未来时间的账单。

## 范围变更规则

- 文档冻结后，任何新增 P0 功能都必须记录变更原因、影响页面、数据模型影响和验收标准变更。
- 若新增功能会改变数据模型或统计口径，必须先更新第 3、4 份文档，再进入开发。
- P1/P2 功能只做架构预留，不提前实现界面和交互。
- 已冻结的验收标准不得用“实现后再补”替代。

## P0 完成定义

当以下完整链路通过验收时，P0 才算完成：

```text
首次启动
-> 自动创建默认账本和内置分类
-> 新增一笔支出或收入
-> 在账单页和日历中找到该记录
-> 查看详情并修改
-> 删除记录
-> 账单汇总和统计同步更新
-> 重启 App 后数据仍存在
```
